# Top MCP repos: 2026-11-12

## TL;DR
- **Security hardening is the main theme.** MCP Inspector shipped two releases in a week that mostly block SSRF/metadata-address tricks. The C# SDK shipped a session-hijack fix, and the Toolbox made BigQuery writes fail closed.
- **"Skills over MCP" (SEP-2640) is landing across SDKs.** FastMCP, rmcp (Rust), the C# SDK and the Toolbox all added skill discovery or serving this week or last.
- **The spec is stable.** The latest revision is `2026-07-28` (stable since 2026-07-28). SDKs are now polishing it, with OAuth, discovery and session fixes. `server/discover` with `ttlMs`/`cacheScope` appears in the Toolbox.
- **MCP Apps (UI resources) is spreading.** Inspector, the Toolbox and the C# SDK all mention it.
- **Browser and desktop-control servers keep adding isolation.** Playwright MCP has background mode and isolated contexts. A new Windows sandbox server (#5) gives agents a throwaway VM.
- Caveat: GitHub search is full of repos with implausible star counts (e.g. one at 455k stars). I excluded these as likely star-farmed or unverifiable. Hacker News was thin today (a few MCP posts with 0–2 points).

No earlier `ideas/*-mcp-ideas.md` reports exist, so no repeats to flag. "Recent gain" for stars is **unknown** for all repos, because the API gives totals only. Star counts are as of 2026-11-13 UTC.

## 1. modelcontextprotocol/inspector
**What it is:** Official MCP Inspector, owned by the `modelcontextprotocol` org. TypeScript. License is reported as "Other" (NOASSERTION); check the LICENSE file. Tooling: inspector/debugger. GitHub describes it as "Deterministic testing tools for MCP servers".

**Why it's here:** Major security-heavy releases in the last 7 days.
- [2.15.0](https://github.com/modelcontextprotocol/inspector/releases) (2026-11-12): the fetch guard now blocks cloud-metadata addresses outside 169.254.0.0/16. `mcpdo` authenticates its daemon before sending it credentials. Env var values are shown in full in the server.json preview, and runtime-control variables need confirmation. It adds per-tool run history, session listing and termination in the web UI, and OAuth debug tracing. It also adds `--load` testing (scenarios, histograms, ramped load, multi-process workers).
- 1.0.5 (v1 line, 2026-11-11): the proxy now blocks 100.100.100.200 and 192.0.0.192.
- 2.14.0 (2026-11-04): stops an MCP App from navigating out of its sandbox frame, restricts server.json imports and URL elicitation to http(s), and bounds the time spent on server-supplied schema patterns.

**What it solves:** Lets you connect to a server, list and call tools, inspect OAuth flows, and now load-test. It is for anyone building or debugging an MCP server.

**General design:** A web UI, a TUI and a CLI (`mcpdo`) share a proxy layer that speaks stdio and HTTP transports to the server under test. Because it can fetch URLs and run server commands, much of the release churn is hardening its own SSRF and sandbox boundaries. I did not read the source, so internals beyond the release notes are not verified.

**Traction:** 11,287 stars, 1,569 forks, 17 open issues, created 2024-10-03, 67 watchers. Recent star gain: unknown. Latest release 2.15.0 (2026-11-12).

**Takeaway for a macOS MCP server builder:** Use it for load and session testing of your Go server. Its SSRF blocklist (metadata IPs, 100.64/10 carve-outs) is a useful checklist if your server ever fetches URLs.

## 2. PrefectHQ/fastmcp
**What it is:** FastMCP, by Prefect. Python, Apache-2.0. Tooling: framework for MCP servers and clients.

**Why it's here:** Very active release train.
- [v4.2.0a5](https://github.com/PrefectHQ/fastmcp/releases) (prerelease, 2026-11-13): `SkillManifestProvider` serves skill metadata lazily. `SkillCatalogProvider` no longer re-hashes every file per request. Dependencies can own a tool argument via `CallArgument`. Logging helpers work in background tasks.
- v4.2.0a4 (2026-11-10): requires Python 3.11+, adds `Annotated` dependencies, and bumps joserfc and Authlib for security fixes.
- v4.1.8 (stable, 2026-11-10): backports 28 fixes, including OAuth proxy token revocation, proxied sampling, and GitHub session keep-alive.

**What it solves:** Cuts the boilerplate for writing an MCP server in Python, and covers auth, proxying and OpenAPI import.

**General design:** Decorator-based tool definitions with type hints generating the schemas. Dependency injection through `Depends(...)` and `CurrentContext()`. Supports stdio and HTTP, an OAuth proxy, and server composition. Skills are served as MCP resources.

**Traction:** 28,406 stars, 2,587 forks, created 2024-11-30. Gain unknown. Also the base of other servers in this list (#10 uses it).

**Takeaway for a macOS MCP server builder:** It is the main Python competitor to hand-rolled servers. Its dependency-injection pattern and lazy skill serving are worth looking at.

## 3. googleapis/mcp-toolbox
**What it is:** Google's open-source MCP server for databases (BigQuery, Looker, Snowflake, MSSQL, Dataplex and more). Go, Apache-2.0. Server.

**Why it's here:**
- [v1.17.0](https://github.com/googleapis/mcp-toolbox/releases) (2026-11-13): an OAuth discovery/token CORS proxy for client-side OAuth in Looker, new Looker tools for dashboards and layouts, `server/discover` results now include `ttlMs` and `cacheScope`, and a Snowflake `list_tables` filter fix.
- v1.16.0 (2026-11-05): skills over MCP and dynamic UI resources. BigQuery `writeMode` now fails closed for non-SELECT statements. The tools config is watched for reloads.
- v1.15.0 (2026-10-23): MCP Apps UI in the playground, plus an issuer-claim validation fix.

**What it solves:** Gives agents governed access to enterprise databases without writing a server per database.

**General design:** A single Go binary driven by a declarative tools config (YAML). Each tool is a parameterized query or prebuilt integration. Auth is centralized through an `authRequired` check, and the config hot-reloads.

**Traction:** 16,854 stars, 1,799 forks, created 2024-06-07. Gain unknown.

**Takeaway for a macOS MCP server builder:** It is a Go server with declarative tool config and hot reload. Both are worth copying: tools defined in config, not code. Fail-closed write modes are a good safety pattern for destructive tools.

## 4. modelcontextprotocol/rust-sdk (rmcp)
**What it is:** Official Rust SDK for MCP. Rust. License reported as "Other"; check the file. Tooling: SDK.

**Why it's here:**
- [rmcp 3.10.0](https://github.com/modelcontextprotocol/rust-sdk/releases) (2026-11-12): loads skills from a directory tree, and fixes tools being dropped when they have dependency property-name maps.
- rmcp 3.9.0 (2026-11-05): Skills extension support (SEP-2640), structured protected-resource discovery errors, and 14 fixes (OAuth scope refresh, SIGTERM before killing a child process, `outputSchema` generation, stateful session cancellation).

**What it solves:** Type-safe servers and clients in Rust, with `#[tool]` and `#[prompt]` macros.

**General design:** Async (tokio) with attribute macros that derive schemas from Rust types. Supports stdio and streamable HTTP, with OAuth client support.

**Traction:** 4,112 stars, 708 forks, 72 open issues, created 2025-02-18. Gain unknown.

**Takeaway for a macOS MCP server builder:** Mostly relevant as an SDK comparison. The Go-side equivalent is the official Go SDK, which I did not check today. The graceful-shutdown change (SIGTERM before kill) is relevant if you spawn helper processes.

## 5. shanselman/sandbox-mcp
**What it is:** By Scott Hanselman. JavaScript, MIT. Server plus CLI (`sbx`). Both use the same core (`src/core.js`).

**Why it's here:** New repo, created 2026-11-06, already 422 stars.

**What it solves:** Gives an agent a disposable Windows 11 machine built on Windows Sandbox, to deploy an app, drive its UI, collect evidence, then delete the machine. Useful for testing installers and running suspicious files.

**General design:** About 30 tools: `sandbox_run/start/stop`, `sandbox_exec`, `sandbox_copy_in/out`, `sandbox_screenshot`, `sandbox_click/type`, `sandbox_ui_tree`, `sandbox_ui_action`, `sandbox_record_*`, `sandbox_install_test`, `sandbox_detonate`, `sandbox_snapshot`, `sandbox_diff`. A PowerShell agent inside the guest does exec, file copy, screenshots, input and UI Automation, since the stock `wsb` CLI returns only exit codes. Transport to the guest is TCP on the NAT address, or a shared-folder "mailbox" (about 100 ms per call) in no-network mode. Messages are described as using HKDF-SHA256 keys, AES-256-CBC and HMAC-SHA256 with replay counters. Safety: Hyper-V isolation, network modes `on`/`firewall`/`off`, clipboard and devices off by default, only three shared folders, `SANDBOX_MCP_ALLOWED_ROOTS`, an `audit.jsonl` log, and a 30-minute idle watchdog. The README itself warns the sandbox is not a guarantee.

**Traction:** 422 stars, 21 forks, 4 watchers, 60 commits on main. Created 2026-11-06. Discussion not found.

**Takeaway for a macOS MCP server builder:** The closest conceptual neighbor to desktop automation. Borrow the UI-tree plus action tools, the audit log, the allowed-roots env var and the idle watchdog.

## 6. microsoft/playwright-mcp
**What it is:** Microsoft's Playwright MCP server. TypeScript, Apache-2.0. Server (browser automation). Established.

**Why it's here:** [v0.0.85](https://github.com/microsoft/playwright-mcp/releases) (2026-11-09): `--background` with `--extension` keeps the connected tab and window inactive; `--no-tab-group`; `locateOnlyVisible`; better snapshot naming; custom form controls via native labels. v0.0.84 (2026-10-31) added isolated contexts via `isolatedContext`, `redactUrlParams`, bounded `browser_find`, and `--ignore-roots`.

**What it solves:** Lets agents drive a real browser using accessibility snapshots instead of screenshots.

**General design:** stdio or HTTP, with tools like `browser_navigate`, `browser_find`, `browser_tabs`. Page state is exposed as structured accessibility snapshots, so it needs no vision model.

**Traction:** 39,572 stars, 3,429 forks, created 2025-03-21. Gain unknown. This is a borderline pick: the updates are incremental, but it is the most-used browser server.

**Takeaway for a macOS MCP server builder:** Background mode (don't steal focus) is a key UX feature for any desktop automation. Accessibility-tree snapshots are the same idea as macOS AX trees. URL-parameter redaction in tool output is also worth copying.

## 7. modelcontextprotocol/csharp-sdk
**What it is:** Official C# SDK, built with Microsoft. C#. License reported as "Other". Tooling: SDK.

**Why it's here:**
- [v2.4.0](https://github.com/modelcontextprotocol/csharp-sdk/releases) (2026-11-07): experimental Skills support in a new `ModelContextProtocol.Extensions.Skills` package. **Traction:** 4,628 stars, 847 forks, 221 open issues, created 2025-03-10. Gain unknown.

**Takeaway for a macOS MCP server builder:** The session security fix is a reminder to bind stateful session IDs to the authenticated identity if your Go server runs over HTTP. I did not read the advisory details.

## 8. github/github-mcp-server
**What it is:** GitHub's official MCP server. Go, MIT. Server.

**Why it's here:** [v2.1.0](https://github.com/github/github-mcp-server/releases) (2026-11-03): two experimental artifact tools (create, read, update, delete), a fix for the merged state in PR lists, rejection of integers at or above 2^63, and dependency updates. v2.0.3 (2026-10-21) returns a resource link for files over 1 MB and moved to Go 1.27.3 as a mitigation for a compromised CA. This is a moderate update, and it sits at 8 because the news is smaller than the others.

**General design:** A Go server with typed tools, exposed over stdio or remote HTTP.

**Traction:** 34,421 stars, 5,341 forks, created 2025-03-04. Gain unknown.

**Takeaway for a macOS MCP server builder:** Another Go reference. Returning a resource link instead of a huge payload is a good pattern for large outputs.

## 9. modelcontextprotocol/registry
**What it is:** The community registry service for MCP servers. Go. License reported as "Other". Tooling: registry.

**Why it's here:** [v1.8.9](https://github.com/modelcontextprotocol/registry/releases) (2026-11-10): faster incremental-sync pagination, plus staged production autoscaling and deployment guardrails (see issue #1840). v1.8.8 (2026-11-06): release body not readable.

**What it solves:** A canonical, API-queryable list of servers that clients and aggregators can sync from. Publishing your server here makes it discoverable.

**Traction:** 7,467 stars, 1,052 forks, 117 open issues, created 2025-02-05. Gain unknown. Operational releases, so this is borderline.

**Takeaway for a macOS MCP server builder:** Publish your server to the registry via a `server.json`.

## 10. gogoymh/auto-ontology-mcp (borderline)
**What it is:** Python (3.12+), Apache-2.0, built on FastMCP, SQLAlchemy and sqlglot. Server. It adapts NVIDIA's Auto Ontology as a semantic layer.

**Why it's here:** New (created 2026-11-06) with 383 stars. **Borderline:** 383 stars against 4 watchers and 13 commits is star-heavy, the README has heavy promotion and a request for stars, and there are no releases. I included it only because the design is interesting. Its demo outputs and benchmarks are unverified.

**What it solves:** Answers questions over databases with SQL checked against a business ontology, and keeps a personal knowledge base. No LLM API key is needed, because the client's model does the language work and the server does deterministic work in local SQLite.

**General design:** About 35 tools. Transport is stdio or streamable HTTP, with a token required for non-localhost access. Connected databases are opened read-only. `AUTO_ONTOLOGY_TOOLSETS=answer` limits the exposed toolset (README claims about 52k to 12k characters of tool definitions).

**Traction:** 383 stars, 53 forks, created 2026-11-06.

**Takeaway for a macOS MCP server builder:** Toolset selection via an env var to shrink tool-definition context is a cheap idea worth borrowing.
