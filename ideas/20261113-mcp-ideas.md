# Top MCP repos: 2026-11-13

## TL;DR
- **Reference servers got a security sweep.** `modelcontextprotocol/servers` v2.4.0 (2026-11-11) fixes six vulnerabilities in the filesystem, git and fetch servers. These are path-confinement, git-config code-execution and SSRF-style bugs. The same bug classes keep showing up across MCP tooling this week (Inspector, Toolbox).
- **"Skills over MCP" (SEP-2640) keeps spreading.** FastMCP 4.2.0 (2026-11-13) now serves skills from the server. Toolbox 1.16.0 added them a week earlier, and the TypeScript SDK had them in 2.4.0.
- **Phone control is the new "computer use" frontier.** Two new repos (Pinky, Poki) let agents drive a real iPhone or Android phone. Pinky is written in Go and puts approval enforcement in a gateway, not in prompts.
- **The spec is quiet.** The newest revision is still `2026-07-28`. Work is SDK and server polish: caching hints (`ttlMs` / `cacheScope` in `server/discover`), OAuth fixes, session limits.
- Caveats: GitHub search again returns repos with implausible star counts (e.g. 458k stars for a 7-month-old repo). I excluded them. The Go SDK, TypeScript SDK and Python SDK had no release in the last 7 days (latest: Go v1.8.0 on 2026-09-14, TS v2.4.0 on 2026-10-23, Python v2.3.0 on 2026-10-02), so they are not listed. Hacker News and Reddit were not checked in depth today.

## 1. modelcontextprotocol/servers
**What it is:** The official collection of reference MCP servers (filesystem, git, fetch, time, memory and others), owned by the `modelcontextprotocol` org. TypeScript (with Python servers). License is reported as "Other" (NOASSERTION); check the LICENSE file. Server.

**Why it's here:** [v2.4.0](https://github.com/modelcontextprotocol/servers/releases) (2026-11-11) fixes six security vulnerabilities.
- Filesystem 2.3.0: read tools open files relative to the checked directory, and `move_file` moves only the source it verified (this closes check-then-use races).
- Git 2026.11.11: repo config can no longer make the server run programs, and `--repository` confinement now covers alternate object stores and linked worktrees.
- Fetch 2026.11.11: IPv6 site-local addresses are refused, and robots.txt is checked against the resolved path.
- Upgrade trap: users of the date-versioned filesystem package must install 2.3.0 explicitly, because package managers won't offer it as an upgrade.
- Earlier this week: v2.3.0 (2026-11-04) added a filesystem `--read-only` mode, a fetch `--allowed-hosts` allowlist, and a Streamable HTTP Docker mode.

**What it solves:** Gives every MCP client a safe, well-known set of file, git and web tools, and serves as the example code other server authors copy.

**General design:** Each server is a small separate package using the official SDKs. They run over stdio, and now also over Streamable HTTP in Docker. Tools are declared with schemas and annotations. Safety is mostly path confinement and allowlists set by command-line flags. I did not read the source beyond the release notes.

**Traction:** 91,977 stars, 11,964 forks, 18 open issues, created 2024-11-19. Latest release v2.4.0 (2026-11-11). Recent star gain: unknown.

**Takeaway for a macOS MCP server builder:** The fixes are a checklist for any file-touching Go server: resolve and verify a path once and then operate on the verified handle (not the string), confine across symlinks and worktrees, and offer a read-only mode and per-directory scopes.

## 2. PrefectHQ/fastmcp
**What it is:** The most popular Python framework for building MCP servers and clients. Owner PrefectHQ. Python. License: see repo (not re-checked today). Tooling: framework.

**Why it's here:** Also featured 2026-11-12; since then: [v4.2.0 "Mad Skills"](https://github.com/PrefectHQ/fastmcp/releases) shipped on 2026-11-13 (previously only alpha/4.1.8).
- Server-hosted skills: `SkillCatalogProvider` registers skills next to the tools they describe, so one deployed server updates every agent.
- `Client.read_skill()` verifies each file's size and digest, and `to_directory()` installs a skill into an agent's local skills folder.
- Skills work with mounts, proxies, `ClientGroup` and `AuthMiddleware`.
- Dependencies can be declared in `Annotated` type hints. Fixes across OpenAPI, proxies, auth, telemetry and tasks.
- Breaking: needs Python 3.11+, and the 4.1 skills API is deprecated (removal in 4.3). `Skill` is now the authoring class and the wire model is `MCPSkill`. 120 contributors, 46 of them first-time.

**What it solves:** Lets Python developers expose functions as MCP tools with little boilerplate, and now distribute agent instructions ("skills") along with the tools.

**General design:** Decorator-based tool/resource/prompt registration, with providers, middleware, proxies and server mounting. Supports stdio and HTTP transports and auth middleware. Not re-verified in detail today.

**Traction:** 28,406 stars (11-12 report); forks and contributor totals unknown. Latest release v4.2.0 (2026-11-13).

**Takeaway for a macOS MCP server builder:** Skills shipped next to tools is becoming a standard idea. A Go server could ship a "how to use these macOS tools safely" skill and serve it over MCP.

## 3. DIYgod/pinky
**What it is:** A desktop app (macOS, Windows, Linux) that lets AI agents operate a real Android phone or iPhone, with the user watching and approving risky steps. Owner DIYgod. Go (single binary, no cgo, native GPU-drawn UI). Apache-2.0. Server (phone control) plus its own agent. The README calls it "pre-alpha".

**Why it's here:** New repo, created 2026-11-06, about 2,100 stars in a week. Pushed within the last day. Topics include `mcp-server` and `claude-code`.

**What it solves:** Agents can't touch phone-only apps. Pinky gives Claude Code, Codex, Cursor and others a controlled way to do it, without handing them unsupervised control.

**General design:**
- MCP over stdio (`pinkyctl mcp`) or HTTP with an agent token. The daemon and clients talk over a Unix socket (named pipe on Windows). Tailscale is used for remote access.
- Named tools include `phone_drag`, `phone_launch`, `phone_app`, `phone_logs`, `phone_device` and `phone_task_*` (run, wait, status, list, steer, cancel). The README does not list all of them.
- Android uses adb plus a bundled scrcpy server. iOS uses Apple developer services on iOS 27+, and WebDriverAgent-based "Pinky on the iPhone" on iOS 17.4–26.
- Safety is enforced in a gateway, not by prompting. Risky steps (payments, sends, deletes, calls, installs, settings changes) wait for a click, and unanswered approvals time out after 60 s as denied. Banking, wallet and password apps are hidden by default, one-time codes are masked, agents can't type into password fields, each agent gets approved scope, and every run is recorded locally. The README admits that an agent with shell access could bypass it via adb, so sandbox the agent.
- SQLite history, FFmpeg for mirroring and recording.

**Traction:** 2,096 stars, 228 forks, 21 open issues, created 2026-11-06. No release checked.

**Takeaway for a macOS MCP server builder:** It is the closest design match to your project: Go, a native app, MCP over stdio and HTTP. Worth borrowing: a gateway-level approval step that returns a "pending approval" status to the agent, timeouts that deny, default-hidden sensitive apps, masking of one-time codes, a global stop hotkey, and run recordings.

## 4. modelcontextprotocol/inspector
**What it is:** Official MCP Inspector for testing and debugging servers. TypeScript. License "Other" (NOASSERTION). Tooling: inspector.

**Why it's here:** Also featured 2026-11-12; since then there is no newer release. [2.15.0](https://github.com/modelcontextprotocol/inspector/releases) (2026-11-12) is the same one covered yesterday and is kept because it is still the biggest tooling update this week. Highlights: more cloud-metadata addresses blocked in the fetch guard, `mcpdo` verifies the daemon's identity before sending credentials, server.json preview shows env values and asks for confirmation, per-tool run history, session listing and termination, `--oauth-debug` tracing, a broader `--load` toolset, and a smaller hardened Docker image. 1.0.5 (2026-11-11) blocks 100.100.100.200 and 192.0.0.192 on the deprecated v1 line.

**What it solves:** Lets you call tools, inspect OAuth flows and now load-test a server.

**General design:** Web UI, TUI and `mcpdo` CLI over a proxy that speaks stdio and HTTP. Much of the churn is hardening its own SSRF boundary.

**Traction:** 11,287 stars (11-12 report), 1,569 forks, created 2024-10-03.

**Takeaway for a macOS MCP server builder:** Use `--load` and `--oauth-debug` to test your server, and note that Inspector now warns before running a server.json command.

## 5. googleapis/mcp-toolbox
**What it is:** Google's open-source MCP server for databases (BigQuery, Snowflake, SQL Server, Looker and more), configured via `tools.yaml`. Go (per my understanding; not re-verified). License: see repo. Server.

**Why it's here:** Also featured 2026-11-12; since then: [v1.17.0](https://github.com/googleapis/mcp-toolbox/releases) (2026-11-13) adds an OAuth discovery/token CORS proxy for client-side OAuth in Looker, new Looker tools for data app extensions, dashboards and layouts, `ttlMs` / `cacheScope` in the `server/discover` result, and a fix limiting Snowflake `list_tables` filters to the configured schema. v1.16.0 (2026-11-05) added skills over MCP, dynamic UI resources, and fail-closed BigQuery `writeMode`.

**What it solves:** Safe, declarative database access for agents without writing a server per database.

**General design:** Tools defined in YAML and hot-reloaded when `tools.yaml` changes. Supports OAuth-based auth for Looker.

**Traction:** 16,854 stars (11-12 report); other numbers not re-fetched.

**Takeaway for a macOS MCP server builder:** Declarative tool config with hot reload, and "fail closed" write modes, are both worth copying (Go, so the code is relevant).

## 6. homeassistant-ai/ha-mcp
**What it is:** An MCP server that lets AI assistants configure and automate Home Assistant (entities, helpers, automations, history). Owner homeassistant-ai. Python. MIT. Server.

**Why it's here:** New this week: [v9.2.0](https://github.com/homeassistant-ai/ha-mcp/releases) (2026-11-11) and a run of `9.3.0.dev` builds through 2026-11-14. Highlights: helper flows run through Home Assistant Core's own flow handling, unit tests run against real Core, `ha_list_services` takes descriptions from Core, all `ha_mcp_tools` services are admin-only, secret flow fields are redacted, and `ha_get_history` treats offset-less timestamps as local time. Borderline: it is a steady release stream, not a single headline change.

**What it solves:** Lets an agent safely edit smart-home configuration, not just toggle devices.

**General design:** Tools such as `ha_get_history`, `ha_list_services` and entity-registry tools, plus an `ha_mcp_tools` integration. The webhook proxy is typed against Core 2026.11.

**Traction:** 7,762 stars, 471 forks, created 2025-09-14.

**Takeaway for a macOS MCP server builder:** Running tests against the real target system (here, real Home Assistant Core) rather than mocks is a pattern worth copying for a macOS server. Admin-only gating and secret redaction are also good defaults.

## 7. microsoft/playwright-mcp
**What it is:** Microsoft's MCP server for browser automation using Playwright accessibility snapshots. TypeScript. License: see repo. Server.

**Why it's here:** Also featured 2026-11-12; since then there is no newer release. [v0.0.85](https://github.com/microsoft/playwright-mcp/releases) (2026-11-09) adds `--background` with `--extension` (keeps the tab inactive and the window unfocused), `--no-tab-group`, a `locateOnlyVisible` option, and better snapshot names for dialogs and landmarks. v0.0.84 (2026-10-31) added isolated contexts, `--redact-url-params`, and `browser_find` limits.

**What it solves:** Lets agents drive a real browser without screenshots.

**Traction:** 39,572 stars (11-12 report).

**Takeaway for a macOS MCP server builder:** Background mode (acting without stealing focus from the user) is exactly the problem a macOS automation server has. URL-parameter redaction in tool output is also useful.

## 8. JosssphZhou/poki
**What it is:** An iPhone app plus companion tools that let AI agents operate a real iPhone, with no jailbreak or extra hardware. Swift. AGPL-3.0. Borderline for this list: the README says the standalone "Poki MCP" server is no longer updated, and the main product is now the Poki app and agent. The repo is still tagged `mcp`.

**Why it's here:** New repo, created 2026-11-05, with 1,119 stars. Pushed within the last day.

**What it solves:** Hands-on control of iOS apps by an agent, with approvals.

**General design:** iOS 27+ uses native iPhone services. iOS 18–26 uses an XCTest session (UI Automation must be on). A computer connects over USB (usbmuxd), with RemotePairing over LAN or Tailscale mentioned. A VPN app must route 10.7.0.1 back to the device. Payments, deletions and Wallet actions always ask, and other approvals are configurable and show on the Lock Screen. Screen contents are sent to the configured model service. I could not find a list of MCP tool names.

**Traction:** 1,119 stars, 199 forks, 77 open issues, created 2026-11-05. Latest release: unknown.

**Takeaway for a macOS MCP server builder:** Mostly a comparison to Pinky. Note the AGPL license and the per-task approval gate on the device itself.

## 9. modelcontextprotocol/registry
**What it is:** The official MCP server registry (the service behind registry.modelcontextprotocol.io) and the `mcp-publisher` CLI. Go. License: see repo. Tooling: registry.

**Why it's here:** Also featured 2026-11-12; since then: [v1.8.9](https://github.com/modelcontextprotocol/registry/releases) (2026-11-10 in the release feed, so it may have been listed yesterday already). It speeds up incremental-sync pagination by selecting indexed page keys before fetching payloads, and adds staged production autoscaling and deployment guardrails. Binaries come with SBOMs and Sigstore signatures. Modest update, kept for ecosystem importance.

**What it solves:** A single place to publish and discover MCP servers.

**Traction:** 7,467 stars (11-12 report).

**Takeaway for a macOS MCP server builder:** Publish with `mcp-publisher` and ship signed, SBOM-backed macOS binaries in the same way (both arm64 and amd64).

## 10. repoprompt/repoprompt-ce
**What it is:** Community edition of RepoPrompt, a native macOS app for context engineering that talks to agents (Claude Code, Codex) and exposes an MCP interface. Swift. Apache-2.0. Borderline: MCP is one feature of a larger app, and its newest release is 7 days old, at the edge of the window.

**Why it's here:** [v1.9.0](https://github.com/repoprompt/repoprompt-ce/releases) (2026-11-06) redesigns the Agent Mode sidebar with Chats and Overseers tabs, makes self-started Claude Code runs visible and controllable, and improves Re-prompt. v1.8.1 (2026-11-02) was an emergency startup fix for older macOS versions and added macOS 15 launch and MCP smoke tests on ARM and Intel. It also fixes MCP session handling.

**What it solves:** Lets you build exact context for a coding agent from a Mac-native UI.

**General design:** Native macOS app with an MCP surface. Detailed tool list: not checked.

**Traction:** 993 stars, 139 forks, created 2026-05-12.

**Takeaway for a macOS MCP server builder:** It is a real example of a shipping Swift macOS app with MCP. The v1.8.1 lesson: smoke-test MCP launch on older macOS versions and on both Intel and ARM before release.
