# Top MCP repos: 2026-11-14

## TL;DR
- **Safety is moving into the server's own design.** Radar splits read and write tools onto separate endpoints. GitLab MCP has `readonly` / `modify` / `full` modes. StackQL's `run_select_query` now refuses writes in every mode. Pinky puts approvals in a gateway the agent can't talk around.
- **Tool-count control is a real design problem.** GitLab MCP has 288 tools but loads only 40 by default, with a `discover_tools` call to turn on more. Loading everything would cost about 73k tokens of schema.
- **"Skills over MCP" keeps spreading.** FastMCP 4.2.0 (2026-11-13) and rmcp 3.10.0 (2026-11-12) both serve or load skills. Toolbox had it earlier in 1.16.0.
- **Servers for GUI apps need to handle modal dialogs.** ue-mcp (Unreal Engine) now detects native editor dialogs that block the app, and refuses calls until the dialog is dealt with. This is the same issue a macOS automation server has with alerts and sheets.
- **Quiet spec.** I found no new spec revision this week. The reports from 11-12 and 11-13 name `2026-07-28` as the latest. I did not re-check the spec repo today.
- Caveats: GitHub search again returned repos with implausible star counts (e.g. 460k stars on a 7-month-old repo) and clusters of near-identical Blender "copilot" repos created within minutes of each other. I excluded them as likely star-farmed. Hacker News and Reddit were not checked today.

## 1. skyhook-io/radar
**What it is:** Radar, by skyhook-io. Go. Apache-2.0. Server (Kubernetes) with a UI. Ships as one binary.

**Why it's here:** [v1.20.3](https://github.com/skyhook-io/radar/releases) (2026-11-13) and v1.20.2 (2026-11-09). 1.20.2 added MCP Helm release workflows and in-cluster Service checks. 1.20.3 added Deployment pause/resume, pod file upload, an AppImage desktop build and other UI work. Created 2026-01-20.

**What it solves:** Answers "what is broken in my cluster, why, and what changed", for people and for agents.

**General design:** The MCP server is on by default and shares the UI's port (9280) over HTTP. There are two endpoints: `/mcp-readonly` (read tools only) and `/mcp` (adds restart, scale, apply, rollback, GitOps sync, node drain, marked destructive so clients can confirm). `--mcp-read-only` disables `/mcp`, and `--no-mcp` disables both. Calls use Radar's Kubernetes access: your kubeconfig locally, or each user's own RBAC when auth (`proxy` or `oidc`) is on. Secret reads omit `.data`; env vars, Helm values and logs are scrubbed for known secret patterns, and the README admits this can't catch everything. `exec_pod` is opt-in, and `--disable-exec` removes it. I did not read the source.

**Traction:** 4,126 stars, 273 forks. Created 2026-01-20. Latest release v1.20.3 (2026-11-13). Discussion links: none found.

**Takeaway for a macOS MCP server builder:** Two endpoints (read-only vs. read-write) is a simple way to let users grant less. It works well with clients that scope permissions per URL.

## 2. xerj-org/xerj
**What it is:** XERJ, by xerj-org. Rust. Apache-2.0. A search engine (Elasticsearch-compatible API) plus an MCP server, for code, docs, logs, JSONL/CSV and PDFs. Server, **borderline**: 19k stars in about 4.5 months is fast, and I could not verify it independently. The product itself looks real (signed releases, CI-checked tool list).

**Why it's here:** Frequent releases. In the last week it published signed "corpus packs" (rust-vulns, agent-session-trajectories) on 2026-11-09, built with 1.0.0-rc.102 and installed with `--verify-sig`. Packs use immutable releases and refuse to be used past 30 days stale.

**What it solves:** Gives agents local BM25, vector and hybrid search, memory and code search through one tool surface.

**General design:** `xerj mcp` is a stdio MCP server that forwards to a running XERJ node over HTTP (`XERJ_URL`, default `localhost:9200`). It exposes about 24 tools (search, semantic/vector/hybrid search, `xerj_memory_store`/`_recall`, `xerj_code_search`, hub and admin tools). Tool schemas are generated from a live `tools/list` and checked in CI. The MCP layer adds no security of its own: the node's boundary applies. `--insecure` makes every caller a superuser. A fresh node binds only to 127.0.0.1. `xerj_autoindex_remove` does nothing without `confirm: true`. Search results default to an 8,000-word budget.

**Traction:** 19,088 stars, 1,419 forks, 226 open issues. Created 2026-06-30. Latest tagged releases are the corpus packs; no standard version release found. Discussion links: none found.

**Takeaway for a macOS MCP server builder:** Two ideas: a default result-size budget on tools, and generating the documented tool list from the live `tools/list` so docs can't drift. It also warns to use an absolute binary path, since desktop-launched hosts don't inherit your shell PATH.

## 3. zereight/gitlab-mcp
**What it is:** MCP server for the GitLab API, by zereight. TypeScript. MIT. Server.

**Why it's here:** Two security-focused releases: [v2.3.27](https://github.com/zereight/gitlab-mcp/releases) (2026-11-13) quotes arguments in compact-result replay commands for POSIX shells, switches `excluded_file_patterns` to a linear-time RE2 engine (max 50 patterns of 200 characters), and bumps `hono`. v2.3.26 (2026-11-12) hardens GraphQL mutation detection in modify mode and rejects unparseable GraphQL in the read-only and modify guards.

**What it solves:** Lets agents work with GitLab (issues, merge requests, pipelines, wikis) with fine control over what they may do.

**General design:** Transports: stdio, SSE (legacy) and Streamable HTTP. Auth: personal access token, local browser OAuth, an MCP OAuth proxy for remote clients, or per-caller tokens via headers (`REMOTE_AUTHORIZATION`). It has 288 tools, with 40 loaded by default (38 `core` plus `discover_tools` and `help`, about 12k tokens); `GITLAB_TOOLSETS=all` costs about 73k. `GITLAB_PERMISSION_MODE` is `readonly`, `modify` or `full`. There is also tool allow-lists and a deny regex. The `api` toolset bypasses these checks, and the README says so. It installs via npm, Homebrew or a `.mcpb` bundle. Legacy options like `GITLAB_READ_ONLY_MODE` go away in v3.0.0.

**Traction:** 2,105 stars, 371 forks. Created 2025-02-11. Latest v2.3.27. Discussion links: none found.

**Takeaway for a macOS MCP server builder:** If your server exposes many tools, a small default set plus a `discover_tools` call is a proven way to save context. Permission modes (read / modify / full) are also easy to copy.

## 4. db-lyon/ue-mcp
**What it is:** Unreal Engine toolkit exposed as MCP tools, by db-lyon. C++. MIT. Server.

**Why it's here:** Beta releases on 2026-11-14 and 11-15 ([v1.4.14-beta.5](https://github.com/db-lyon/ue-mcp/releases)). beta.4 reads native OS dialogs from the editor process (GPU device removed, assertion prompts, missing module) from outside the editor, and refuses every tool call, naming the dialog, while one is open. `editor(list_dialogs)` and `editor(respond_to_dialog)` let the agent inspect and answer them. beta.5 reports drop-downs, text boxes and whether buttons are enabled, and refuses to press disabled buttons. It also adds CSV DataTable import.

**What it solves:** Stops agent calls from hanging or failing silently when the editor is stuck behind a dialog.

**General design:** Tools are grouped as `editor(...)`, `asset(...)` and so on, with the action as an argument. There is a daemon with endpoints that list and press dialogs by window handle. I did not read the README, so transport and auth are unverified. The dialog feature is Windows-specific by its description.

**Traction:** 503 stars, 77 forks. Created 2026-02-24. Latest v1.4.14-beta.5 (2026-11-15, pre-release). Discussion links: none found.

**Takeaway for a macOS MCP server builder:** Directly relevant. A blocked-by-dialog check that fails fast with the dialog's name, and tools to list and answer dialogs, map onto macOS alerts and sheets. This is worth copying in spirit.

## 5. stackql/stackql
**What it is:** SQL framework for querying and managing cloud and SaaS resources, with an MCP server. By stackql. Go. MIT. Server, **borderline**: its main product is a SQL engine, and the release is 9 days old, slightly outside the 7-day window. I included it because the MCP changes are the main news.

**Why it's here:** [v1.0.888](https://github.com/stackql/stackql/releases) (2026-11-05), the first 1.x release. Every tool now publishes a `title` and explicit `readOnlyHint`, `destructiveHint` and `openWorldHint`. `run_select_query` refuses INSERT, UPDATE, REPLACE, MERGE, UPSERT, DELETE and EXEC in every mode and points to `run_mutation_query` or `run_lifecycle_operation`. It ships `.mcpb` bundles for six platforms (including a darwin universal bundle), an npm launcher with provenance, and a Claude plugin bundle.

**What it solves:** Lets agents query and change cloud resources with SQL while keeping reads and writes separate.

**General design:** Caller identity can come from JWT, bearer digests, mTLS or the local OS user. Secrets are session-scoped, with OS secret stores opt-in. I did not read further.

**Traction:** 1,080 stars, 93 forks. Created 2022-01-03. Latest v1.0.888. Discussion links: none found.

**Takeaway for a macOS MCP server builder:** Split read and write tools by name, annotate every one, and make the "read" tool reject writes itself. Shipping a universal darwin `.mcpb` is also useful.

## 6. DIYgod/pinky
**What it is:** App and MCP server for operating real Android and iPhone devices, by DIYgod. Go. Apache-2.0. Server. Pre-alpha. Also featured 2026-11-13 (rank 3); since then, stars went from 2,096 to 2,171 and it was pushed again on 11-15. I did not find a new release.

**Why it's here:** Still new (created 2026-11-06), and the design is interesting.

**What it solves:** Lets an agent use a phone while a person watches and approves risky steps.

**General design:** One Go binary (`pinkyctl`), stdio via `pinkyctl mcp` or HTTP with an agent token. Android uses adb and scrcpy, iPhone uses Xcode's Device Hub (iOS 27+) or a WebDriverAgent helper. Approval rules run in a gateway between the agent and the phone: a step needing approval returns `approval_pending`, nothing happens until the user clicks Allow, and 60 seconds of silence counts as no. Banking, wallet and password apps are hidden by default, and agents can't type into password fields.

**Traction:** 2,171 stars, 236 forks, 25 open issues, 3 watchers. Created 2026-11-06.

**Takeaway for a macOS MCP server builder:** Approval enforced outside the model, with a timeout that defaults to deny, and a default-hidden list of sensitive apps.

## 7. PrefectHQ/fastmcp
**What it is:** Python framework for MCP servers and clients. Apache-2.0. Tooling: framework. Also featured 2026-11-12 and 11-13.

**Why it's here:** [v4.2.0](https://github.com/PrefectHQ/fastmcp/releases) (2026-11-13) is the final release after a series of alphas. The server can serve agent skills (`SkillCatalogProvider`); `Client.read_skill()` checks each file's size and digest. Dependencies can be declared with `Annotated`. Python 3.11+ is required, and the 4.1 skills API is deprecated, to be removed in 4.3. Alphas (11-10 to 11-13) tightened redirect URI handling and raised joserfc and Authlib minimums for security fixes. Since the 11-13 report, I found no later release.

**What it solves:** Lets Python authors define tools with decorators and type hints, instead of writing protocol code.

**General design:** Not re-read today; see the earlier reports.

**Traction:** 28,469 stars, 2,594 forks. Created 2024-11-30. Latest v4.2.0.

## 8. modelcontextprotocol/inspector
**What it is:** The official MCP Inspector (web UI, TUI, CLI). TypeScript. License reported as "Other" (NOASSERTION). Tooling: inspector. Also featured 11-12 and 11-13.

**Why it's here:** [2.15.0](https://github.com/modelcontextprotocol/inspector/releases) (2026-11-12) blocks more cloud-metadata addresses, authenticates the `mcpdo` daemon before sending credentials, and adds load testing (scenarios, latency histograms, baselines, multi-worker), per-tool run history, session termination and `--oauth-debug` tracing. 1.0.5 (11-11) patched the deprecated v1 line. Nothing newer found.

**What it solves:** Connect to a server, call tools and debug OAuth.

**General design:** As described in the 11-12 report. I did not re-read the source.

**Traction:** 11,287 stars (earlier report). Latest 2.15.0.

**Takeaway for a macOS MCP server builder:** The new `--load` mode is a cheap way to test your server under repeated calls.

## 9. googleapis/mcp-toolbox
**What it is:** Google's MCP server for databases. Go. Server. Also featured 11-12 and 11-13.

**Why it's here:** [v1.17.0](https://github.com/googleapis/mcp-toolbox/releases) (2026-11-13) adds a Looker CORS proxy for OAuth discovery and token requests, Looker dashboard tools, `ttlMs` / `cacheScope` in `server/discover` results, and limits the Snowflake `list_tables` filter to the configured schema. v1.16.0 (11-05) added Skills over MCP, dynamic UI resources and a fail-closed BigQuery `writeMode`.

**What it solves:** Declarative database tools defined in `tools.yaml`, which reloads when changed.

**Traction:** 16,854 stars (earlier report). Latest v1.17.0.

## 10. modelcontextprotocol/rust-sdk
**What it is:** Official Rust SDK (`rmcp`). Tooling: SDK. Not featured before in the last two reports' top 10 apart from 11-12 rank 4.

**Why it's here:** [rmcp 3.10.0](https://github.com/modelcontextprotocol/rust-sdk/releases) (2026-11-12): loads skills from a directory tree, keeps tools that use dependency property-name maps, and documents the Send limitation on async `#[tool]`/`#[prompt]` bodies. Also featured 2026-11-12; since then this is a newer release than the one covered then (as far as I could tell).

**What it solves:** Rust servers and clients using macros for tools and prompts.

**Traction:** 4,112 stars (earlier report). Latest rmcp-v3.10.0.
