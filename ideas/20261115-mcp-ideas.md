# Top MCP repos: 2026-11-15

## TL;DR
- **Security hardening is the common theme in releases.** chrome-devtools-mcp 1.12/1.13 reject `devtools://` URLs, redact WebSocket headers, block script evaluation while a dialog is open, and can refuse `file:` navigation. Tableau MCP 6.0.4 binds a local listener to loopback and scopes upload keys per tenant. Playwright MCP 0.0.84 adds `redactUrlParams` to hide tokens in tool output.
- **Context cost is a first-class concern.** context-mode (v2.2.0, 2026-11-14) keeps tool output out of the model's context and returns only searched excerpts. It now supports 11 agents.
- **Background / non-intrusive automation.** Playwright MCP 0.0.85 added `--background`, so the controlled tab doesn't steal focus. That is the same "don't disturb the user's desktop" problem a macOS automation server has.
- **Calendar, BI and audio servers keep arriving.** Remote OAuth 2.1 servers (keeper.sh, Tableau's hosted `mcp.tableau.com`) sit next to fully local servers running on-device models (audio-studio-mcp on Apple Silicon).
- **Spec is quiet.** The latest spec release I found is `2026-07-28` (stable, 2026-07-28). I saw no newer tag in the spec repo's releases. SDKs (TypeScript 2.4.0, Python 2.3.0, Go 1.8.0) are all on it.
- Caveats: GitHub search again returned implausible star counts (e.g. 460k stars on a 7-month-old repo) and clusters of near-identical Blender "copilot" repos created within minutes. I excluded them as likely star-farmed. I did not check Hacker News or Reddit today. "Recent star gain" is **unknown** everywhere, because the API gives totals only. ## 1. ChromeDevTools/chrome-devtools-mcp
**What it is:** chrome-devtools-mcp, by the Chrome DevTools team. TypeScript. Apache-2.0. Server (browser debugging/automation). [Repo](https://github.com/ChromeDevTools/chrome-devtools-mcp).

**Why it's here:** [v1.13.0](https://github.com/ChromeDevTools/chrome-devtools-mcp/releases) (2026-11-11). New: logpoints built on DevTools' BreakpointManager, page-scoped network mocks, upstream network mock responses. Fixes: UTF-8 BOM config files accepted, `Error.cause` chain capped at 10, `set_logpoints` disabled under `--no-javascript-evaluation`. Lower memory use in the network collector. The v1.12.0 notes (2026-10-22) add parallel page-scoped tool calls, `--watchConfig`, and refusal of `devtools://` URLs.

**What it solves:** Lets a coding agent inspect a real Chrome: performance traces, network, console, heap snapshots, Lighthouse. Aimed at people having agents debug web apps.

**General design:** Node server over stdio, driving Chrome via DevTools/Puppeteer. Tools are named actions (`navigate_page`, `evaluate_script`, `lighthouse_audit`, `set_logpoints`, and so on). Safety is through flags: `--file-navigations` to reject `file:` URLs, URL policy enforced across redirects, WebSocket headers redacted from logs, `evaluate_script` blocked while a dialog is open. I did not read the source.

**Traction:** 57,182 stars, 4,822 forks. Created 2025-09-11. Latest release v1.13.0 (2026-11-11). Contributors: unknown. Discussion links: none found today.

**Takeaway for a macOS MCP server builder:** "Block script execution while a modal dialog is open" and a `--no-javascript-evaluation`-style kill switch are cheap guards worth copying for any tool that runs arbitrary actions in an app.

## 2. microsoft/playwright-mcp
**What it is:** Playwright MCP, by Microsoft. TypeScript. Apache-2.0. Server (browser automation). [Repo](https://github.com/microsoft/playwright-mcp).

**Why it's here:** [v0.0.85](https://github.com/microsoft/playwright-mcp/releases) (2026-11-09): `--background` keeps the connected tab inactive and its window unfocused and opens new tabs in the background; `--no-tab-group`; `locateOnlyVisible`; better snapshot names for dialogs, landmarks and tables; custom form controls found via `<label>`. v0.0.84 (2026-10-31) added `redactUrlParams`, `isolatedContext` for tabs, `--ignore-roots` and locator `target` input in several languages. Also featured on 2026-11-12/13 reports; since then this release shipped.

**What it solves:** Gives agents structured, accessibility-tree-based browser control without screenshots.

**General design:** stdio server (HTTP also available, per my earlier reports; not re-verified today). Snapshots of the accessibility tree give the model element references. Redaction of URL params limits token leaks into the model's context. I did not read the source.

**Traction:** 39,702 stars, 3,443 forks. Created 2025-03-21. Latest release v0.0.85 (2026-11-09). Contributors: unknown.

**Takeaway for a macOS MCP server builder:** A `--background` mode that avoids stealing focus is exactly the behavior users want from desktop automation. Also consider `redact…` options for secrets in tool output.

## 3. mksglu/context-mode
**What it is:** Context Mode, by mksglu. JavaScript. Elastic License 2.0 (source-available, not open source; GitHub shows NOASSERTION). Tooling: MCP server plus agent hooks that manage context size. [Repo](https://github.com/mksglu/context-mode).

**Why it's here:** [v2.2.0](https://github.com/mksglu/context-mode/releases) (2026-11-14) adds OMP (oh-my-pi) as the 11th supported agent, a `safeFetch` that sends user-agent/accept headers and names the refused host, and fixes for Gemini CLI, Codex and Windows hooks. v2.1.9 and v2.1.10 followed on 2026-11-12. Large repo; the update is incremental, so this is a borderline "major update" pick, justified by its size and momentum.

**What it solves:** Big tool outputs (logs, files, web pages) eat the model's context. Context Mode runs commands, indexes the full output locally, and returns only what the agent searches for. Its README claims a median 99.4% reduction in output bytes over 36 benchmark rows. That is the author's own figure, which I haven't verified.

**General design:** Tools `ctx_execute`, `ctx_batch`, `ctx_index`, `ctx_search`, `ctx_resume`, `ctx_stats`, `ctx_doctor`, `ctx_upgrade`, `ctx_purge`. Output is chunked (≤4,096 B) into two SQLite FTS5 tables (Porter and trigram), ranked with BM25 and merged with Reciprocal Rank Fusion. `PreToolUse` hooks steer the agent to `ctx_*` tools. A journal and a ≤2,048 B state block restore session state after context compaction. The README says "sandbox" means keeping output out of context, **not** security isolation: scripts run as your user. Zero telemetry per README.

**Traction:** 34,159 stars, 2,348 forks. Created 2026-02-23. Latest release v2.2.0 (2026-11-14). It is a single-maintainer project per the README. Star count is large for its age; I couldn't verify it isn't inflated.

**Takeaway for a macOS MCP server builder:** If your tools can return large output (window trees, file listings), cap and paginate, or index and search it, rather than dumping it into the context.

## 4. tableau/tableau-mcp
**What it is:** Tableau MCP, official, by Tableau. TypeScript. Apache-2.0. Server (BI / analytics). [Repo](https://github.com/tableau/tableau-mcp).

**Why it's here:** [v6.0.4](https://github.com/tableau/tableau-mcp/releases) (2026-11-09) and v5.5.0 (2026-11-04). 6.0.4 adds the `tableau:entitlements:read` OAuth scope (with strict scope matching, older tokens need re-consent), tenant-scoped staged-upload S3 keys, field selectors on `get-datasource-metadata`, and Desktop tools `close-workbook` and `list-saved-datasources`. **Breaking:** `invokeCommand` and the command tools are removed. The Desktop web profile listener now binds to loopback (`HTTP_HOST` to change). 5.5.0 made `apply-workbook` refuse changes that would delete sheets.

**What it solves:** Lets agents query Tableau data sources, find workbooks and views, and (in Desktop) author workbooks.

**General design:** Hosted at `https://mcp.tableau.com` with per-user OAuth 2.1, or self-hosted via npx/Docker/binary with PAT environment variables (`PAT_NAME`, `PAT_VALUE`, `SERVER`, `SITE_NAME`). Needs Node 22.7.5+. Stdio and HTTP configs exist in the repo. Tool categories weren't listed on the page I could read. Feature flags gate authoring tools.

**Traction:** 375 stars, 153 forks (a high fork ratio, likely corporate use). Created 2025-05-02. Latest release v6.0.4. Contributors: unknown.

**Takeaway for a macOS MCP server builder:** Removing a generic "run any command" tool in favor of specific tools, and having apply operations refuse destructive diffs, are good safety patterns. Binding local listeners to loopback by default is a must.

## 5. ridafkih/keeper.sh (borderline)
**What it is:** keeper.sh, by ridafkih. TypeScript. AGPL-3.0. Calendar sync product with a built-in MCP server (server: calendar). Borderline because MCP is a feature of a bigger product. [Repo](https://github.com/ridafkih/keeper.sh).

**Why it's here:** Pushed 2026-11-16 (UTC) and described as a "universal calendar MCP server" across Google, Outlook, iCloud, CalDAV and ICS. I found no release notes or dates, so the "major update" is unconfirmed. It is here for being a useful, new-ish calendar server.

**What it solves:** One MCP endpoint for reading and editing events across calendar providers, finding free time, answering invitations and managing iCal feeds.

**General design:** 27 tools (calendars, events, sync control, iCal feeds, `send_feedback`). A single `streamable-http` remote at `https://www.keeper.sh/mcp`; self-hosted at `/mcp`. OAuth 2.1 with a consent screen that grants read and write. Some settings tools need a Pro plan.

**Traction:** 1,470 stars, 79 forks. Created 2025-12-23. Latest release: unknown. Contributors: unknown.

**Takeaway for a macOS MCP server builder:** Direct competition for any Calendar.app tooling, though it goes through provider APIs, not the local app.

## 6. kanaworksai-hue/audio-studio-mcp
**What it is:** audio-studio-mcp, by kanaworksai-hue. Python. MIT. Server (audio generation). [Repo](https://github.com/kanaworksai-hue/audio-studio-mcp).

**Why it's here:** New, created 2026-10-18; 673 stars in under a month.

**What it solves:** Generates background music, loops and sound effects locally, with no cloud service. For game and video makers working through an MCP client.

**General design:** Four tools: `generate_audio` (1-4 candidates), `edit_audio` (restyle, regenerate a range, extend), `process_audio` (trim, loop, fade, normalize, export WAV/OGG/FLAC), `unload_models`. Stdio by default via `uvx audio-studio-mcp`; `--http 8765` serves `/mcp` on 127.0.0.1; `--web` adds a UI. Runs Stable Audio 3: MLX on Apple Silicon (about 7 GB download), PyTorch on NVIDIA. Needs `uv` and `ffmpeg`. Weights are gated on Hugging Face (Windows path).

**Traction:** 673 stars, 51 forks. Created 2026-10-18. Releases: none listed. Contributors: unknown.

**Takeaway for a macOS MCP server builder:** An `unload_models`-style tool for freeing resources, and a localhost-only HTTP option next to stdio, are small touches worth noting.

## 7. Graphicle-AI/graphicle
**What it is:** Graphicle, by Graphicle-AI (KarLex AI, Inc.). Rust. Apache-2.0. Server (code graph and project memory). [Repo](https://github.com/Graphicle-AI/graphicle).

**Why it's here:** New, created 2026-10-14; pushed 2026-11-16. Borderline: it follows the tool names of Graphify (`query_graph`, `get_neighbors`, `shortest_path`) and its traction is small; I couldn't check for star-farming beyond the plausible numbers.

**What it solves:** Gives coding agents a queryable graph of a repo plus stored decisions and past sessions, with answers cited to file and line.

**General design:** One Rust binary, local only (127.0.0.1), one SQLite file. tree-sitter parsing for code; Markdown, PDF, Office and HTML docs indexed too. Python and TypeScript SDKs. Transport for MCP isn't stated on the page. Works with Claude Code, Codex, Cursor, VS Code and others. No telemetry per README.

**Traction:** 579 stars, 44 forks. Created 2026-10-14. Version 0.1.17 mentioned in README (not labelled as latest). Contributors: unknown.

**Takeaway for a macOS MCP server builder:** Single static binary with embedded SQLite is the same shape as a Go server; a useful reference for local-only packaging.

## 8. modelcontextprotocol/go-sdk (borderline)
**What it is:** The official Go SDK for MCP servers and clients, maintained with Google. Go. License shown as NOASSERTION on GitHub (not verified further). Tooling: SDK. [Repo](https://github.com/modelcontextprotocol/go-sdk).

**Why it's here:** Pushed 2026-11-13, but the latest release I found is [v1.8.0](https://github.com/modelcontextprotocol/go-sdk/releases) (2026-09-14), which is outside the 7-day window. It's included because it is the SDK your server likely builds on. v1.8.0 added limits on JSON nesting, SSE events, stdio frames and OAuth registration responses, `SupportedProtocolVersions`, a `SetCacheable` hook, and fixes for session leaks and teardown hangs. Two behavior changes sit behind `MCPGODEBUG` flags, which are to be removed in v1.9.0.

**What it solves:** A supported Go implementation of the protocol, including spec 2026-07-28.

**General design:** Go library for both servers and clients; stdio and streamable HTTP transports; OAuth support.

**Traction:** 5,349 stars, 621 forks, 55 watchers. Created 2025-04-23.

**Takeaway for a macOS MCP server builder:** Direct dependency. Watch for v1.9.0, which removes the `MCPGODEBUG` flags, and check that your build doesn't rely on them.

## 9. github/github-mcp-server (borderline)
**What it is:** GitHub's official MCP server. Go. MIT. Server. [Repo](https://github.com/github/github-mcp-server).

**Why it's here:** [v2.1.0](https://github.com/github/github-mcp-server/releases) (2026-11-03) is 12 days old, so slightly outside the window; included as a notable release. It adds two experimental artifact-management tools, fixes PR list merged state, and rejects integer parameters at or above 2^63. v2.0.3 (2026-10-21) returned resource links for files over 1 MB and moved to Go 1.27.3 to address a compromised CA.

**What it solves:** Repos, issues, PRs, and workflows for agents.

**General design:** Go, with remote and local modes; tools use typed parameters and validation. I did not re-read the source today.

**Traction:** 34,505 stars, 5,357 forks. Created 2025-03-04.

**Takeaway for a macOS MCP server builder:** A mature Go server to study for tool design, pagination and resource links for large content.
