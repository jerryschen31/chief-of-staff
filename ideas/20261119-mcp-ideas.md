# Top MCP repos: 2026-11-19

## TL;DR
- **Security hardening dominates releases.** `modelcontextprotocol/servers` v2.5.0 (Nov 18) fixes eight vulnerabilities in the git, filesystem and everything servers. That follows six more in v2.4.0 (Nov 11). The C# SDK (Nov 3/7), Rust SDK, mcp-go and Java SDK all shipped bounded-buffer, OAuth or session fixes in the last two weeks.
- **Spec `2026-07-28` is landing in the SDKs.** Java SDK v2.2.0 (Nov 16) adds a stateless "modern" client and server for it, in a new `io.modelcontextprotocol.modern` package. Roots, sampling and logging are deprecated (SEP-2577). No newer spec revision has appeared.
- **Skills over MCP is now cross-language.** Rust (rmcp 3.10/3.11), C# (v2.4.0, experimental `Extensions.Skills`) and goose (v1.60.0, skills replace its Skills extension) all shipped skills support within about two weeks.
- **A new niche: testing agents against mocked CLIs and MCP servers.** Dynobox appeared on Show HN on Nov 19. Details are thin (see its entry).

## 1. modelcontextprotocol/servers
**What it is:** The official collection of reference MCP servers (git, filesystem, fetch, memory, everything and others). TypeScript (with Python servers such as git and fetch). The API lists the license as "Other" (NOASSERTION). Server. [Repo](https://github.com/modelcontextprotocol/servers).

**Why it's here:** Also featured 2026-11-13 and 2026-11-14. Since then:
- [v2.5.0](https://github.com/modelcontextprotocol/servers/releases/tag/v2.5.0) (2026-11-18) is a security release fixing eight vulnerabilities in three servers.
  - mcp-server-git 2026.11.18: merges no longer run git maintenance, lazy fetch is disabled, index entries outside the working tree are refused, and submodule config can no longer run programs.
  - server-filesystem 2.4.0: directory listings are anchored on Linux/macOS, not yet on Windows.
  - server-everything 2.3.1: NAT64 addresses are checked as IPv4.
  - Date-versioned npm installs need an explicit `@2.4.0` install.
- [v2.4.0](https://github.com/modelcontextprotocol/servers/releases/tag/v2.4.0) (Nov 11) fixed six more: git config could no longer run programs, the fetch server treats IPv6 site-local addresses as private, and the filesystem server keeps reads and moves with the checked file.
- [v2.3.0](https://github.com/modelcontextprotocol/servers/releases/tag/v2.3.0) (Nov 4) added `append_file` and `copy_file`, `--read-only` and `--confine-roots` to the filesystem server.

**What it solves:** A reference for what a "normal" MCP server looks like, and the default servers many users run. Aimed at everyone.

**General design:** Each server is a separate npm or PyPI package, mostly stdio. Tools are declared with schemas. Safety is mostly path or host confinement inside the server. The security fixes show the typical failure modes: symlink and TOCTOU races, hostile repo config, and SSRF address-range gaps.

**Traction:** 92,121 stars, 11,987 forks, 11 open issues and PRs (API count). Created 2024-11-19. Latest release v2.5.0.

**Takeaway for a macOS MCP server builder:** The filesystem fixes are a checklist for any server that touches paths: confine to roots, avoid check-then-use races, and offer a `--read-only` mode. Filesystem anchoring is done for Linux/macOS first.

## 2. modelcontextprotocol/java-sdk
**What it is:** The official Java SDK. Java, MIT. Tooling (SDK). [Repo](https://github.com/modelcontextprotocol/java-sdk).

**Why it's here:** [v2.2.0](https://github.com/modelcontextprotocol/java-sdk/releases/tag/v2.2.0) (2026-11-16) adds support for MCP 2026-07-28 through a stateless server and client in the new `io.modelcontextprotocol.modern` package.
- The legacy API is unchanged. The modern API may still change before 3.0.
- Breaking: `McpTransportContext` no longer has content-based `equals`/`hashCode`. For preview users, `McpParamHeaders` was replaced by `McpHeaders` and the completion repository API was removed.
- Roots, sampling and logging are deprecated (SEP-2577).
- The first modern server arrived in [v2.2.0-M1](https://github.com/modelcontextprotocol/java-sdk/releases/tag/v2.2.0-M1) (Oct 16), which the notes say passes 37 required conformance scenarios.

**What it solves:** Lets JVM shops (Spring and others) build MCP servers and clients on the current spec.

**General design:** Two parallel APIs: the older session-based one and the newer stateless one. HTTP transports. Conformance scenarios are used as the acceptance test.

**Traction:** 3,777 stars, 1,106 forks, 279 open issues and PRs (API count). Created 2025-01-20.

**Takeaway for a macOS MCP server builder:** Compare the "stateless" model and the deprecation of roots, sampling and logging with what your Go server relies on. The conformance suite is worth running.

## 3. modelcontextprotocol/rust-sdk
**What it is:** The official Rust SDK (`rmcp` crates). Rust, license "Other" in the API. Tooling (SDK). [Repo](https://github.com/modelcontextprotocol/rust-sdk).

**Why it's here:** Also featured earlier (2026-11-12 and 2026-11-14). Since then:
- [rmcp 3.11.0](https://github.com/modelcontextprotocol/rust-sdk/releases/tag/rmcp-v3.11.0) (Nov 17) merges cache hints across list pages, rejects unadvertised capability methods by default (this may change behavior), avoids refreshing short-lived tokens on every call, and bounds buffered Streamable HTTP responses.
- [rmcp 3.10.0](https://github.com/modelcontextprotocol/rust-sdk/releases/tag/rmcp-v3.10.0) (Nov 12) added loading skills from a directory tree.

**What it solves:** Type-safe MCP servers and clients in Rust.

**General design:** Procedural macros (`rmcp-macros`) define tools from annotated functions. Releases are tagged per crate.

**Traction:** 4,129 stars, 721 forks, 67 open issues and PRs (API count). Created 2025-02-18.

**Takeaway for a macOS MCP server builder:** "Reject unadvertised capability methods by default" is a cheap strictness check to copy.

## 4. mark3labs/mcp-go
**What it is:** The most widely used community Go MCP SDK. Go, MIT. Tooling (SDK). [Repo](https://github.com/mark3labs/mcp-go).

**Why it's here:** [v1.6.0](https://github.com/mark3labs/mcp-go/releases/tag/v1.6.0) (2026-11-19). The release body is empty, so its highlights are **unknown**. The two earlier releases:
- [v1.5.0](https://github.com/mark3labs/mcp-go/releases/tag/v1.5.0) (Oct 30): `WithManualInputRoundTrips`, bounded SSE message-endpoint bodies, and bounded HTTP client reads.
- [v1.4.0](https://github.com/mark3labs/mcp-go/releases/tag/v1.4.0) (Oct 26): about 20 fixes, including integer request IDs kept through cancellation, atomic registry replacement, and OAuth callbacks bound to their transaction.

**What it solves:** MCP servers and clients in Go, without the official SDK.

**General design:** Builder-style server API, with stdio, SSE and streamable HTTP transports.

**Traction:** 9,245 stars, 956 forks, 70 open issues and PRs (API count). Created 2024-11-27.

**Takeaway for a macOS MCP server builder:** This is a direct dependency candidate (or competitor) for a Go server. Compare it with the official `modelcontextprotocol/go-sdk` (featured 11-17 at 1.9.0-pre.1). Check what v1.6.0 changed before upgrading.

## 5. ChromeDevTools/chrome-devtools-mcp
**What it is:** The Chrome DevTools team's MCP server that lets coding agents drive and debug Chrome. TypeScript, Apache-2.0. Server. [Repo](https://github.com/ChromeDevTools/chrome-devtools-mcp).

**Why it's here:** Also featured 2026-11-14, 15 and 16. Since then, nothing newer than [v1.13.0](https://github.com/ChromeDevTools/chrome-devtools-mcp/releases/tag/chrome-devtools-mcp-v1.13.0) (Nov 11) that I found. It adds logpoints built on the DevTools BreakpointManager, page-scoped network mocks and upstream network mock responses. `set_logpoints` is disabled under `--no-javascript-evaluation`. Borderline on recency (8 days).

**What it solves:** Lets an agent inspect, debug and profile a live browser page.

**General design:** Local stdio server on Puppeteer and DevTools. Security flags include `--file-navigations` (rejects `file:` navigation) and redaction of WebSocket headers in logs (v1.11/1.12). v1.12 runs independent tool calls in parallel and adds `--watchConfig` to reload config.

**Traction:** 58,409 stars, 4,878 forks, 135 open issues and PRs (API count). Created 2025-09-11.

**Takeaway for a macOS MCP server builder:** Config hot reload, parallel independent tool calls, and per-capability opt-out flags are all worth borrowing.

## 6. upstash/context7
**What it is:** An MCP server that serves current library documentation to agents. TypeScript, MIT. Server. [Repo](https://github.com/upstash/context7).

**Why it's here:** Patch releases on 2026-11-17: [mcpb-v4.7.3](https://github.com/upstash/context7/releases/tag/mcpb-v4.7.3) and [ctx7@0.12.2](https://github.com/upstash/context7/releases/tag/ctx7%400.12.2). The CLI patch reverts the rules and skills text that `ctx7 setup` installs, dropping guidance for the source-code and upgrade-guide tools. The server now describes its experimental tools only to users who enabled them. Weak update: borderline, included for its size and its MCP Bundle (`.mcpb`) packaging.

**What it solves:** Stops agents from hallucinating outdated APIs.

**General design:** Hosted docs index behind an MCP server, plus a `ctx7` CLI. It ships as an MCP Bundle for one-click install.

**Traction:** 65,152 stars, 3,277 forks, 60 open issues and PRs (API count). Created 2025-03-26.

**Takeaway for a macOS MCP server builder:** Telling the model about experimental tools only when enabled keeps the tool list small. Shipping an `.mcpb` bundle is a distribution path for Claude Desktop.

## 7. aaif-goose/goose
**What it is:** An open-source local AI agent that uses MCP servers as extensions. Rust, Apache-2.0. Tooling (client/host). [Repo](https://github.com/aaif-goose/goose).

**Why it's here:** [v1.60.0](https://github.com/aaif-goose/goose/releases/tag/v1.60.0) (Nov 17) adds a skills operation that replaces its Skills extension. It also adds two providers and makes cron validation run before schedule changes. Chat mode and the `goose review` subcommand were removed, MSRV rose to 1.95.0, and the minimum macOS rose to 13. [v1.60.1](https://github.com/aaif-goose/goose/releases/tag/v1.60.1) (Nov 18) has one fix (the compaction fix, unverified). The MCP piece is the skills change, so this is borderline for the scope.

**What it solves:** A free, local agent host for MCP users.

**General design:** Rust core with desktop and CLI front ends. MCP servers load as extensions.

**Traction:** 56,803 stars, 6,630 forks, 479 open issues and PRs (API count). Created 2024-08-23.

**Takeaway for a macOS MCP server builder:** goose is a client to test your server against. Its macOS 13 minimum is a hint about the audience.

## 8. modelcontextprotocol/csharp-sdk
**What it is:** The official C# SDK. C#, license "other" in the API. Tooling (SDK). [Repo](https://github.com/modelcontextprotocol/csharp-sdk).

**Why it's here:** Borderline: the release is 12 days old. [v2.4.0](https://github.com/modelcontextprotocol/csharp-sdk/releases/tag/v2.4.0) (Nov 7) adds experimental Skills (`ModelContextProtocol.Extensions.Skills`) and requires explicit opt-in for the legacy OAuth metadata fallback. [v2.3.1 and v1.4.2](https://github.com/modelcontextprotocol/csharp-sdk/releases/tag/v1.4.2) (Nov 3) are security patches for authenticated sessions, plus PKCE and issuer validation. v1.4.2 says to enable `AllowLegacyOAuthMetadataFallback` only after confirming PKCE enforcement.

**What it solves:** MCP servers and clients on .NET.

**General design:** Dependency-injection style hosting, with OAuth support for HTTP transports.

**Traction:** 4,641 stars, 854 forks, 228 open issues and PRs (API count). Created 2025-03-10.

**Takeaway for a macOS MCP server builder:** If you add HTTP transport with OAuth, copy the validation of PKCE support and the metadata issuer.

## 9. shanselman/sandbox-mcp
**What it is:** An MCP server and `sbx` CLI for running untrusted software in Windows Sandbox. JavaScript, MIT. Server. [Repo](https://github.com/shanselman/sandbox-mcp).

**Why it's here:** Also featured 2026-11-12. Since then, [v1.2.0](https://github.com/shanselman/sandbox-mcp/releases/tag/v1.2.0) (Nov 7) added interactive-desktop screenshots, bounded desktop recording with HTML playback and optional MP4, an authenticated TCP and offline-mailbox transport with replay rejection, and an agent-led setup guide with checksum verification. Borderline: the release is 12 days old and it is a young, small repo.

**What it solves:** Lets an agent run installers and unknown binaries safely.

**General design:** 21 tools plus a CLI. Network modes: on, firewall, off. Default runs never install app prerequisites. Requires Windows 11 24H2 Pro or better, with no ARM64 build.

**Traction:** 490 stars, 25 forks, 1 open issue or PR (API count). Created 2026-11-06.

**Takeaway for a macOS MCP server builder:** Screenshots, bounded recording and explicit network modes make a good model for a desktop-automation tool surface.
